## Umbraco 18 OpenAPI Notes
- Umbraco 18 uses `Microsoft.AspNetCore.OpenApi`; avoid adding back Swashbuckle registration.
- Do not use old `SwaggerGenOptions`, `SchemaIdHandler`, `OperationIdHandler`, or `BackOfficeSecurityRequirementsOperationFilterBase`.
- Register plugin backoffice OpenAPI through `builder.AddBackOfficeOpenApiDocument(...)`.
- The Mailjet API document name is `newsletter-studio-plugin`; the generated endpoint is:
  - `http://localhost:54108/umbraco/openapi/newsletter-studio-plugin.json`
- Preserve operation IDs from controller action names, lower-cased first, so the generated frontend keeps `MailjetResource.getConfiguration` and `MailjetResource.configureNow`.

## Newsletter Studio 18 API Notes
- `IEmailServiceProvider` requires `ValidateSettingsAsync(Dictionary<string, object>)`.
- Bounce and public services use async methods:
  - `SetTrackingItemErrorAsync`
  - `SetRecipientPermanentErrorAsync`
  - `GetMailingListsForAllWorkspacesAsync`
- Prefer converting call paths to async rather than blocking on async methods.

## Frontend Notes
- Run frontend commands from `src/NewsletterStudio.Plugins.Mailjet/Client`.
- `npm install` updates `package-lock.json`.
- `npm run generate:api` requires the sample site running on `http://localhost:54108`.
- Do not add a direct `@hey-api/openapi-ts` dependency; use the version brought in by Umbraco 18 backoffice packages.
- `package.json` Volta and `.nvmrc` should pin Node `24.15.0`.
- Frontend package baselines are `lit@^3.3.1`, `typescript@^6.0.3`, and `vite@^7.3.2`.
- In `openapi-ts.config.ts`, use the modern `@hey-api/sdk` operation config:
  - `strategy: 'byTags'`
  - `container: 'class'`
  - `containerName: '{{name}}Resource'`
- This generator emits operation files plus a fetch runtime layout under `src/backend-api/client` and `src/backend-api/core`.
- Do not reintroduce the old `/umbraco/swagger/.../swagger.json` input path; use `/umbraco/openapi/newsletter-studio-plugin.json`.

## Verification Commands
Run from the repository root unless noted:

```powershell
dotnet restore NewsletterStudio.Plugins.Mailjet.sln --no-cache --verbosity minimal
dotnet build NewsletterStudio.Plugins.Mailjet.sln --no-restore --configuration Debug --verbosity minimal
dotnet build src\NewsletterStudio.Plugins.Mailjet\NewsletterStudio.Plugins.Mailjet.csproj --no-restore --configuration DebugNoFrontendBuild --verbosity minimal
```

Run from `src/NewsletterStudio.Plugins.Mailjet/Client`:

```powershell
npm run build
```

To regenerate the frontend API client:

```powershell
dotnet run --project samples\UmbracoTestSite\UmbracoTestSite.csproj --configuration Debug --urls http://localhost:54108
```

Then, in `src/NewsletterStudio.Plugins.Mailjet/Client`:

```powershell
npm run generate:api
npm run build
```

## Generated Files And Build Side Effects
- `samples/UmbracoTestSite/umbraco-package-schema.json` can be regenerated by Umbraco during build.
- `src/NewsletterStudio.Plugins.Mailjet/Client/src/backend-api` is generated from the sample site's OpenAPI document.
- `src/NewsletterStudio.Plugins.Mailjet/wwwroot/App_Plugins/NewsletterStudio.Plugins.Mailjet/dist` is generated by Vite.
- Leave unrelated untracked agent/tool folders such as `.agents/` and `.codex/` alone unless the user explicitly asks.
